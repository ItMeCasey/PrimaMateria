# Completion report, 2026.11.2 (code complete, not released)

Version 2026.11.2 on all four modules. Nothing pushed, tagged or released.

## Done (evidence)
- **Real fluids** (brine, molten copper, iron, gold) on both loaders and versions; barrels, crucible and casting tray expose the fluid handler; dispensers place buckets. Self test pipe checks pass on all four builds; real-client frames on NeoForge 26.2 and Forge 26.3: `docs/testing/fluids.md`, `docs/frames/fluid_*`.
- **Recipe sync to dedicated-server clients**: proven with a real dedicated server and joining client on NeoForge 26.2 for BEI, JEI and REI (`docs/testing/recipe_sync_*.log`, `docs/frames/sync_*`). Forge 26.3 BEI proof: PASS (real dedicated server plus joining client, 57 sifting recipes sent in 1 frame, 6 frames in `docs/frames/sync_forge-26.3_*`, `docs/testing/recipe_sync_forge-26.3_bei.log`).
- **Sounds and particle**: all 13 sounds and the pour particle are triggered (`scripts/check_sound_triggers.py`).
- **Crystal textures**: five drawn, amethyst placeholder removed, visible under the fluid (`docs/frames/crystal_review.png`).
- **Start island** is now a structure file a datapack can replace (`scripts/make_start_island.py`); code plan stays as fallback.
- **Missing recipe found and added**: 4 rock chips to 1 cobblestone.
- **Texture review sheet** `docs/frames/texture_review.png` refreshed; textures are NOT approved.
- Self tests on all four builds pass (NeoForge 26.2 443, Forge 26.2 446, NeoForge 26.3 444, Forge 26.3 447); `check_data.py` passes. Docs, wiki, CurseForge description and changelog updated.

- **Ore compat** (Casey, 2026-11-14): `docs/ORE_COMPAT.md`. Recipes name convention tags; a result tag resolves to the lowest-id item of the tag (`recipe/ItemRef`), a tag nobody fills does nothing. 95 materials from the 26.2 and 26.3 lists; sifting, crushing, melting, casting; optional tag entries for items without tags. Self test `CompatSelfTest` proves tag resolution, vanilla-by-tag crushing, melting and casting, and that nothing of an absent mod happens. Loader load conditions are not used: tag-based inertness covers it.
- **Fluids for every metal:** 42 molten fluids with source, flowing, block, bucket, textures and names (`fluid/Metals.java` generated by `scripts/make_compat.py`).
- **Why Casey did not see the fluids** (`docs/testing/fluid_visibility.md`): the released 2026.11.1 jar had internal fluids only (no fluid items or blocks); real fluids are in 2026.11.2. In survival: brine from steeping salt dust in a barrel, molten metals from melting in a fired crucible over a heat source, buckets out and placed as real fluid blocks; all buckets are in the creative tab. A tint bug that darkened brine and molten metals in barrels and crucibles twice is fixed.
- **Buckets through the loader (Casey, 2026-11-14):** the id table of buckets is gone (`FluidBuckets` keeps only the 1000 mB volume). The machines read and change the held item through the loader's own item fluid handler (`fluid/ItemFluids`, installed by `NeoForgeItemFluids` over `Capabilities.Fluid.ITEM` with `ItemAccess` and transactions, and by `ForgeItemFluids` over `ForgeCapabilities.FLUID_HANDLER_ITEM`), so any mod's bucket or tank item fills and empties the barrels, the crucible and the casting tray; the machine tanks stay block fluid handlers. Self tests fill and empty each machine with vanilla water and lava buckets and with ours.
- **Furnace drive lit model:** the lit model is now the unlit machine model with only the firebox face swapped to the glowing texture; no other machine had a lit or active model that swaps the shape; `check_data.py` checks that the models of one blockstate share geometry.
- **BEI and fluids:** cause found. (1) BEI's API (`bei-neoforge-26.2-2026.11.7-api.jar`) has no fluid ingredient type: `CustomRecipe.Builder` takes `ItemStack` slots only, so a fluid could only be shown as its bucket item or painted by the card painter. (2) Our cards marked every `primamateria:molten_*` fluid as a "melt" (a tinted square, an item-less slot) from when the molten metals were internal; JEI and REI drew them as squares too. Fixed: all fluids are fluid entries; JEI and REI show them as real fluid ingredients, BEI paints the fluid's still texture in the slot with a name and amount tooltip. What BEI needs to do it properly (blocker for the BEI session): a fluid ingredient in the API (`CustomRecipe.Builder.inputFluid(fluidId, mB)` and `outputFluid(fluidId, mB)`), drawn by BEI with the fluid sprite and amount, a fluids tab in the ingredient list, and recipe lookup by fluid.
