# Sieve animation: test results (workstream C, 2026-11-13)

- **Unit tests** (`common/src/test`, run in every module): keyframe tracks (linear, step, catmull-rom, bezier hard stop, clamping), easing and spring, bone matrices (rotation about a pivot, parents, position and scale), the JSON loader (rejects an expression keyframe, an unknown interpolation, a missing parent or texture, a missing contract bone), the sieve animator (load plop and event, shake clip and fall back to idle, finds reveal and pop, finish and hop, far level stays at rest, arrays reused), and the shipped `sieve.json` (contract bones, all 8 clips, shake swing inside the frame opening, 13 cubes in moving bones). 29 tests (5 more from the scaffold).
- **Headless self test** (`python scripts/server_check.py all`): PASS on neoforge-26.2 (132 checks), forge-26.2 (127), neoforge-26.3 (132), forge-26.3 (127). The workstream C checks: sieve state properties and every state placeable, a block entity that implements `SieveViewSource`, particle types registered and their files present, `sieve.json` loads, every blockstate and model parses with elements inside the block, sounds.json entries and all 27 files present, selection shapes inside the block.
- **Real client** (`python scripts/client_tour.py <layer>`, isolated launcher, 17 frames each): PASS on neoforge-26.2 and forge-26.2. Frames in `docs/frames/primamateria_<layer>_*.png`: sieve at rest from two sides, each of the five mesh tiers, loaded and waiting, two frames mid-shake (plus two more), a thin layer with finds showing, a full load of sand, 20 sieves moving, and the same 20 with `client.animations` reduced and off.
- **Cost with 20 moving sieves in view** (client tour, uncapped frame rate): our renderer code takes 5.5 microseconds per sieve per frame on neoforge-26.2 and 4.7 on forge-26.2, that is about 0.1 ms per frame for 20 sieves; with `reduced` or `off` it takes 2.4 to 3.0 microseconds per sieve. Average frame rate in `full`: 206 (neoforge-26.2) and 204 (forge-26.2) with the rest of the scene. The `reduced` and `off` runs of the same tour reported about 30 fps on both builds, which is the isolated desktop slowing the client after the first measurement, not the renderer (its own time went down), so there is no real frame rate comparison between the three levels yet.
- **Not covered:** the 26.3 client tour (the 26.3 builds are covered by the headless self test only; the tour needs no 26.3-specific code), the 200-sieve hall of `SIFTING.md` (20 were measured), sounds heard in a real game (the launcher mutes the client), the powered drive and auto hammer in a real client.
